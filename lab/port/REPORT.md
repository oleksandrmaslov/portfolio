# Studio look port: final report

This port puts the approved lab look on every public route that draws a model: PBR Neutral tone, the studio PMREM room, the material presets and the hardware finishes. That covers the hero, the landing handoff, the Universe field, the menu, the about-board and the Wafer PLAY DEMO. Owner amendments A1 (the explosions keep the PCB artwork), A2 (`MOStudio.copy` keeps shader hooks) and A4 (`zmk-mark.glb` stays sealed) are in.

State at the end of this stage:
- `npm run build`, `check` and `test` (51 of 51) are green.
- `lab/studio.check.mjs`, `story.check.mjs`, `motion.check.mjs` and `places.check.mjs` all pass.
- The PLAY DEMO probe passes all 12 checks.
- A smoke run over all 15 model routes found no page errors, 404s or `[studio]` warnings.
- The ring walk passes in both directions. Its log is `lab/port/ring.log`.

Nothing is committed. The section "Commands for deploy" lists what has to be added, because several runtime files are still untracked.

The first draws of each landing visit cost four frames of 0.6–1.3 s under SwiftShader. That is SwiftShader compiling already-linked shaders the first time it draws them; the before run also caught one 1,181 ms frame. The steady state was recorded after 120 warm-up frames, and a note in `perf-after.json` says so. One bad landing-title sample was a CDN failure (three.js never arrived from unpkg) and was discarded.

Pixels that are not the models (cards, stars, void, depth of field, measured with the models hidden) are unchanged. Before against after differs by 4.69% of pixels on the title and 3.35% on the reel. The same build against itself differs by 3.15–5.72%, so the change is inside run-to-run noise.

## Fixes from this stage

The independent review raised four low-severity findings. Each was confirmed against the code.

| Finding | Confirmed? | Fix |
|---|---|---|
| `finish()` discarded the unmapped-material list from `finishGlb()`, so a GLB material without a `BY_NAME` row was never reported. That material stays the loader's shared one, and `tone()` and the card fade would then change it for every clone. | Yes. No shipped GLB hits it, and test (f) catches an unknown name in CI. | `finish()` now keeps the list and `console.warn`s once per URL: `[studio] <url>: no preset for <names>`. Test (b) asserts the warning fires once per URL. |
| `demo/wafer-demo.js`: `const SIGNAL` had no reader left | Yes. Its only reader was the removed teal PointLight. | Deleted |
| `studio.js`: `shared()` set `tex.userData.studioShared`, and nothing ever read it | Yes. No dispose path, test or lab script checks the flag. The rule that shared textures are never disposed holds because consumers dispose only `finish().materials`. | Removed `shared()` and its seven call sites. The rule is still documented on `finish()`. |
| The port depends on untracked files while `wafer_demo.glb` is a tracked deletion, so `git commit -a` would ship pages that 404 their models | Yes | No code change. The exact commands are in the next section. |

After the fixes: the build was rerun, `check` passes, the tests pass (51 of 51), and the four lab checks pass. Studio JS is still under the 9.5 KB CI ceiling. The fixes change no pixels, because shipped GLBs have no unmapped materials and the removed flag and constant had no readers. The re-shoot was therefore a behaviour check rather than new sheets:
- The PLAY DEMO probe passed 12 of 12 (output in `lab/port/tmp/stage-final/demo/`).
- A console smoke over all 15 routes, with the menu opened, found no errors, 404s or studio warnings (`lab/port/tmp/stage-final/smoke.cjs`).

## Known issues

- **Shader warm-up on a real GPU.** Each landing visit's first draws cost four 0.6–1.3 s frames under SwiftShader. It is probably a software-renderer artifact, but nobody has measured it on a real GPU.
- **Scroll restore after a reverse flight.** Coming back from a project page lands 800–1,300 px from where the visitor left. The HEAD screenshots show the same thing, so the port didn't cause it.
- **Iskra and Brionel heroes** read darker than their gallery panels. This is unverified at a matched angle.
- **Wafer Studio and Bulgaria poses** differ between the page and the registry. This predates the port and was left alone.
- **Budget overages** in the table above need sign-off.

## Commands for deploy

CI checks out tracked files only, and the deploy rsync ships only what is in the checkout. Run from the repo root:

```sh
# new files the deployed pages and CI need
git add app/projects/rendering/studio.js \
        models/wafer.glb models/venovisor-mark.glb \
        models/wafer-pcb-L.webp models/wafer-pcb-R.webp \
        tools/landing-runtime/studio.test.cjs \
        tools/wafer/

# files the port deleted
git rm --cached app/projects/rendering/solid-materials.js \
                models/wafer_demo.glb \
                tools/landing-runtime/model-decoder.test.cjs

# every modified tracked file: sources, regenerated runtimes and stamped HTML,
# AGENTS.md, docs, ci-clop-mark.glb, and the deploy-pages.yml line
git add -u
```

`git rm --cached` is used because the files are already gone from disk; plain `git rm` works too. `git add -u` also stages the deletions, so the `git rm` line is a safeguard. Leave these out: `Ci-clop-dirty/`, `venovisor model/`, `.agents/` and `skills-lock.json`. `lab/` is untracked and the deploy excludes it anyway; add it only if you want the studies under version control. After staging, `git status` should list no `??` file under `app/`, `models/`, `demo/` or `tools/landing-runtime/`.

One note on `git add -u`: this branch (`codex/audio-refresh`) also carries changes from before the port. `git add -u` stages them as well, so check `git diff --cached --stat` before you commit.
