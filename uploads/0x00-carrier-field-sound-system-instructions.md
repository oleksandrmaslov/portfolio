# 0x00 Carrier Field — Sound System Instructions

**Project:** Oleksandr Maslov personal portfolio  
**Target:** Awwwards / FWA / CSSDA-level interactive portfolio sound system  
**Status:** Creative + production instruction brief only. No code in this document.  
**Core requirement:** Sound must feel authored as part of the object, not added as UI decoration.

---

## 1. The Big Idea

> **0x00 Carrier Field** — a living electro-mechanical universe where every visitor action excites the same root signal, as if the visitor is touching the instrument that holds all project nodes together.

The website is not a page with music. It is a quiet technical field.  
The visitor does not trigger clips. They disturb a living medium.  
The projects are nodes. Oleksandr is `0x00`: the root, the carrier, the fundamental reference signal scattered through the universe.

The sound system must make the site feel like:

> **a silent precision machine revealing a cosmic field when touched.**

---

## 2. Brand Translation: What This Should Sound Like

### Visual identity to sound mapping

| Visual / brand element | Sound equivalent |
|---|---|
| Deep-space graphite substrate | Near-silence, matte low-level noise, distant air, dark but not cinematic |
| Signal-cyan accent | Rare bright signal tones, narrow-band shimmer, clean resonant pings |
| Monospace labels / telemetry | Precise ticks, short confirmations, measured rhythmic micro-events |
| Editorial italic serif numerals | Elegant tonal bends, subtle harmonic color, rare expressive details |
| Fibonacci spacing | Time intervals, decay lengths, modulation rates, and event density based on proportional relationships |
| PCB / oscilloscope motifs | Electric pulses, filtered signal traces, diagnostic sweeps, oscilloscope-like motion coupling |
| Mechanical keyboards / firmware | Physical thock, switch travel, spring resonance, case resonance, tactile confirmation |
| Deep space | Width, depth, distance, slow drift, sparse field energy |

### Tone

Cold. Precise. Restrained. Engineered. Mysterious. Confident.  
Pleasant, never abrasive.  
Minimal, but not empty.  
Rare payoff moments should feel earned.

---

## 3. User Taste Calibration

These preferences must guide all design decisions:

1. The visitor should **enter the field** through a meaningful activation moment.
2. Keyboard recordings are essential identity material. Oleksandr will record multiple mechanical keyboards and edit them cleanly.
3. Different sections/projects may have different feelings, but must share the same sonic DNA, like game UI/OST systems where different screens share motif, sound language, percussion, and palette.
4. Headphones are preferred for the full experience, but the system must still work on laptop speakers.
5. Mouse movement may affect the universe, but only as subtle field disturbance — not as a gimmicky cursor sound.
6. Contrast is welcome, but everything should remain pleasant.
7. The portfolio should lean more **machine + cosmic** than fantasy, horror, or generic sci-fi.

---

## 4. Non-Goals

Do **not** build:

- Generic UI click sounds.
- A background music loop with sound effects on top.
- Cinematic spaceship ambience.
- Harsh glitch/noise aesthetics.
- Overly musical melodies that distract from the portfolio.
- Constant audible feedback for every pixel of cursor movement.
- A novelty toy where sound becomes the main distraction.
- A soundboard of isolated clips.
- A system that depends on high volume, sub-bass, or headphones to make sense.

The sound should be memorable because it feels inevitable, not because it is loud.

---

## 5. Core Sonic Architecture

The system should be organized as one shared acoustic world, not many disconnected assets.

### 5.1 Graphite Substrate

The base state of the site.

- Almost silent.
- Dark, matte, controlled.
- May include barely perceptible filtered noise, low air, or slow electrical drift.
- Should not read as “music playing.”
- Should feel like the field exists even when nothing is happening.
- Must leave enough silence for interaction sounds to matter.

**Design test:** When idle, the site should feel alive, but a visitor should not feel forced to listen to a track.

---

### 5.2 `0x00` Carrier

The root signal.

- A tonal or quasi-tonal foundation that represents Oleksandr as origin.
- Should be subtle enough to disappear into the graphite substrate.
- Can be built from harmonic-series relationships, just-intonation-inspired intervals, or narrow resonant bands.
- Should not become a conventional melody.
- May evolve slowly over time so it never obviously loops.
- Every project/node should relate back to this carrier.

**Design test:** If all transient sounds are removed, the field should still feel like one coherent identity.

---

### 5.3 Mechanical DNA Layer

The physical identity of the site.

Source material:

- Real recordings of Oleksandr’s mechanical keyboards.
- Downstroke, upstroke, stabilizers, spacebar, case resonance, desk resonance, spring ping, switch texture.
- Multiple boards may become different “materials” or node families.

Usage:

- Primary tactile confirmation for keypresses, clicks, major selections.
- Source material for processed resonators and short impulses.
- Micro-percussion for rare rhythmic UI moments.
- Physical excitation source for the field, not just standalone samples.

**Important:** A click should not merely play a thock. A click should feel like a mechanical impulse exciting the entire shared field.

---

### 5.4 Signal-Cyan Accent Layer

The rare bright layer.

- Clean, narrow, precise, luminous.
- Used sparingly for focus, discovery, unlock, successful selection, or high-value transitions.
- Should feel like a telemetry signal, not a notification beep.
- Can be sine-like, glassy, FM-like, resonant, or filtered.
- Must decay naturally back into the graphite substrate.

**Design test:** Cyan sounds should feel expensive because they are rare.

---

### 5.5 Node Atmospheres

Each project/node may have a distinct acoustic shade.

Rules:

- Every node must share the same root carrier DNA.
- Differences should come from distance, filtering, density, rhythm, texture, stereo width, and resonance color.
- Node atmospheres should never feel like different songs from different websites.
- A project can feel warmer, colder, heavier, more mechanical, more human, more abstract — but still inside the same universe.

**Design reference model:** Same DNA, different feeling — more like a coherent game UI/OST family than a playlist.

---

## 6. Interaction Model: Visitor as Disturbance

Every interaction should be understood as energy entering the field.

The system should follow this causal chain:

> **Visitor action → mechanical/electrical impulse → field excitation → spatial bloom → decay back into graphite silence**

Nothing should feel pasted on top.

---

## 7. Interaction Sound Map

### 7.1 First Activation: “Enter the Field”

Purpose: turn browser audio permission into a ritual.

Desired feeling:

- Quiet threshold crossing.
- The system wakes, but does not explode.
- The first sound should establish the root carrier and the acoustic space.
- It should feel like the visitor has powered or touched a precise field instrument.

Possible sonic behavior:

- Very soft mechanical contact.
- Low carrier appears.
- Distant cyan harmonic aligns into focus.
- Space opens subtly around the listener.

Avoid:

- Generic “sound on” toggle.
- Big cinematic boom.
- Startup jingle.

Suggested copy direction:

> **ENTER THE FIELD**  
> Disturb the system.

---

### 7.2 Idle State

Purpose: presence without demand.

Desired feeling:

- The field is live.
- It is watching, measuring, waiting.
- Silence remains the dominant material.

Behavior:

- Slow, non-obvious evolution.
- No obvious loop point.
- Very low density.
- Occasional barely audible signal movement only if it feels natural.

---

### 7.3 Mouse Movement

Purpose: make the universe feel responsive without turning the cursor into a toy.

Desired feeling:

- Mass moving through a field.
- Pressure, proximity, gravity, density.
- The field notices the visitor.

Possible parameters affected by movement:

- Filter openness.
- Stereo bias.
- Reverb send.
- Noise density.
- Carrier modulation depth.
- Node proximity resonance.
- Very subtle pitch or phase drift.

Rules:

- No obvious whoosh on every movement.
- No continuous cartoon sound.
- Movement influence must be subtle, smoothed, and slow enough to feel physical.
- Cursor velocity may create stronger disturbance than position alone.

---

### 7.4 Hover on Nodes / Projects

Purpose: reveal node presence.

Desired feeling:

- The node comes into focus acoustically.
- The visitor is approaching an object in the field.

Behavior:

- Local resonance blooms from the carrier.
- A faint cyan signal may appear.
- The node may pull the stereo image toward itself.
- The ambient bed may subtly make room for the hover response.

Avoid:

- Simple hover beeps.
- Identical hover sound everywhere.
- Sounds that are louder than the visual action deserves.

---

### 7.5 Click / Select Node

Purpose: tactile commitment.

Desired feeling:

- A real mechanical confirmation.
- The system accepts the input.
- The selected node becomes active.

Behavior:

- Use a clean keyboard-derived thock or thock-inspired impulse.
- The thock should excite the shared space.
- A short cyan response may confirm successful selection.
- Ambient field may duck very slightly to let the transient read clearly.

Rules:

- Click confirmation should be satisfying at low volume.
- It should feel physical, not digital.
- It should be consistent enough to become brand identity.

---

### 7.6 Keyboard Input / Keypresses

Purpose: connect the portfolio directly to Oleksandr’s hardware identity.

Desired feeling:

- Real mechanical input.
- Firmware-console precision.
- A keyboard is not just a metaphor; it is the body of the system.

Behavior:

- Keypresses should use real edited keyboard recordings as source DNA.
- Different keys/actions may have subtly different switch colors or materials.
- Repetition should vary slightly to avoid machine-gun sample fatigue.
- The site should never become noisy when typing or navigating quickly.

---

### 7.7 Scroll

Purpose: movement through depth.

Desired feeling:

- The visitor is moving through layers of the field.
- Scroll is spatial, not just vertical.

Behavior:

- Scroll velocity may affect filter, stereo width, field density, or subtle Doppler-like motion.
- Section transitions may reveal new node atmospheres.
- Large scroll events may produce very soft low-frequency pressure or airy shift.

Avoid:

- Obvious scroll whooshes.
- Long transition sounds that fire too often.
- Fatiguing high-frequency movement.

---

### 7.8 Page / Section Transitions

Purpose: reconfigure the universe.

Desired feeling:

- Coordinates change.
- The same field rearranges itself.
- The visitor is still inside one continuous system.

Behavior:

- Old layer decays into the shared space.
- New layer emerges from the same root carrier.
- Transition should be smooth and elegant, not trailer-like.

---

### 7.9 Reward / Discovery Moments

Purpose: create rare moments that keep attention and feel memorable.

Desired feeling:

- Discovery, not gamification.
- The field reveals a deeper layer.
- The visitor is rewarded for attention.

Possible triggers:

- Opening a project.
- Discovering a hidden node.
- Completing a meaningful interaction sequence.
- Reaching a key identity statement.
- Entering the universe after a deliberate pause.

Rules:

- Rewards must be rare.
- They should be beautiful, not loud.
- They should feel like the system briefly aligning around the visitor.

---

### 7.10 Mute / Resume

Purpose: respect and control.

Behavior:

- Mute must be immediate and obvious visually.
- Resume should re-enter gracefully, not restart loudly.
- The sound state should never trap the visitor.
- The system should still be visually complete without sound.

---

## 8. Mixing Philosophy

The system should be mixed as one shared field.

### Required behavior

- Interaction sounds bloom out of the ambient layer and decay back into it.
- Important transients may gently duck the substrate so they feel clear without being loud.
- Reverb/space should be shared across sound families to unify them.
- Sounds should have hierarchy: root field < movement < hover < click/select < rare reward.
- The site must remain pleasant after several minutes.

### Priority order

1. Silence / comfort.
2. Tactile identity.
3. Spatial immersion.
4. Discoverable detail.
5. Musical beauty.

Musicality is welcome, but it must serve the interface and metaphor.

---

## 9. Spatial Philosophy

Headphones should reveal the full universe.

Use spatial design for:

- Node position.
- Cursor proximity.
- Far/near depth.
- Section transitions.
- Hidden details.

But preserve identity on speakers:

- The thock must remain readable.
- The carrier must not rely on sub-bass.
- Cyan accents must not vanish in stereo width.
- Mono compatibility matters.

---

## 10. Technical Direction Without Code

The final implementation may use Web Audio API directly, Tone.js, or a hybrid approach.

The system should support:

- Browser audio activation through the “Enter the Field” moment.
- Live synthesis and procedural modulation where appropriate.
- Use of Oleksandr’s own edited keyboard recordings as local source material.
- Shared reverb/convolution or shared spatial bus.
- Resonator-style excitation from impulses.
- Subtle sidechain-style ducking or dynamic mixing.
- Smoothed cursor-driven parameter modulation.
- Voice pooling so repeated interactions do not overload performance.
- Offline-capable behavior where possible.
- Graceful fallback if audio cannot start.
- Clear mute/resume state.

Do not build an architecture that depends on large external audio libraries, streaming files, or heavy CPU use.

---

## 11. Source Material Instructions

Oleksandr will record keyboards.

Recommended recording targets:

- Single key downstroke.
- Single key upstroke.
- Spacebar.
- Enter key.
- Stabilized keys.
- Fast typing texture.
- Slow deliberate typing.
- Case tap.
- Desk resonance.
- Spring ping / switch resonance if present.
- Multiple keyboards with clearly different material character.

Editing goals:

- Clean noise floor.
- Tight transients.
- Natural decay preserved where beautiful.
- No over-compression.
- Multiple velocity/intensity versions.
- Short files for interaction use.
- Longer texture recordings only if they become subtle source material, not loops.

The recordings should be treated as proprietary brand DNA.

---

## 12. Fibonacci / System Logic

Fibonacci should influence the sound subtly, not become a gimmick.

Possible uses:

- Decay times.
- Delay timings.
- Event spacing.
- Modulation rates.
- Probability weighting.
- Section density.
- Reward timing.
- Node distance relationships.

Example design principle:

> Smaller interactions decay quickly; deeper interactions decay by larger proportional steps.

Avoid making Fibonacci audible as a math demonstration. It should feel like hidden order.

---

## 13. Accessibility and Respect

The sound system must be optional and respectful.

Requirements:

- No autoplay without user action.
- Clear enter/mute state.
- No essential information conveyed by sound alone.
- No sudden loud events.
- No high-frequency pain points.
- No constant fatigue-inducing movement sound.
- Respect reduced-motion style preferences conceptually by also reducing audio intensity if appropriate.
- Default volume should be conservative.

The sound must reward attention, not punish visitors who browse silently.

---

## 14. Implementation Guardrails

When this brief is later turned into a system:

- Do not rely on any previous `.md` files, `sound_lab`, or existing sound-related JS/scripts from the current portfolio archive.
- Use Landing v9 visuals and structure only as contextual reference.
- Do not copy sound, music, samples, or motifs from Valorant, The Finals, Apple, Lusion, Immersive Garden, or any other reference.
- Use references only to understand design principles.
- Do not overbuild before the core identity works.
- Start with one excellent field + one excellent thock + one excellent node hover before expanding.

## 16. Acceptance Criteria

The system succeeds if:

- The sound feels like part of the visual universe, not an add-on.
- The first activation moment is memorable and on-brand.
- The mechanical keyboard identity is immediately felt but not overused.
- Cursor movement makes the field feel alive without becoming annoying.
- Hover and click interactions feel causally connected to the same shared space.
- Different project nodes have variation while still sharing one DNA.
- Silence remains powerful.
- The experience is pleasant after repeated use.
- The sound system works as an award-level differentiator.
- A visitor could describe the site as “the one with the living 0x00 sound field.”

---

## 17. Red Flags During Review

Reject or revise if the system feels like:

- A music player.
- A game menu copied into a portfolio.
- A sci-fi sound pack.
- A bunch of hover/click samples.
- Too busy.
- Too cute.
- Too harsh.
- Too random.
- Too dependent on headphones.
- Too literal with Fibonacci or telemetry.
- Technically impressive but emotionally forgettable.

---

## 18. Open Creative Questions Before Final Design

These should be answered before full implementation:

1. Should `0x00` have a fixed tonal center, or should the root pitch be abstract/non-pitched?
2. Should each project node have its own acoustic material family, or only subtle variations of one material?
3. How much rhythmic identity is allowed before it starts to feel too much like game UI music?
4. Should the “Enter the Field” moment be extremely minimal, or should it be the first rare payoff?
5. Which keyboard should become the primary brand thock?
6. Should node distance in the visual universe map directly to sound distance?
7. Should the site ever become almost completely silent after inactivity?
8. Should there be hidden sonic easter eggs for deep exploration?
9. How much should the system expose its audio state visually, if at all?
10. What is the maximum acceptable audio file footprint if keyboard recordings are used?

---

## 19. One-Sentence Creative North Star

> **Make the portfolio sound like a graphite-black firmware instrument suspended in space, where every visitor action mechanically excites the same living `0x00` carrier field.**
